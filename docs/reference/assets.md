# Assets: models, preloads and Blender levels (SDK 3)

Three layers, from simulation-safe to GPU:

| Layer | Where | What |
|---|---|---|
| `Assets` service (`sdk/assets`) | host, `src/platform/assets.ts`; contract `src/sdk/contracts/assets.ts` | `bytes` / `text` / `json(ctx, path)`, `peek(path)`, `preload(ctx, paths, onProgress?)`, `progress`, `report()`. Cached per path, reference-counted per plugin scope (kernel `AssetStore`), released when the last owner's session scope ends. A failed load is retried on the next request. |
| glTF reader + `spawnGltfScene` | `src/sdk/contracts/gltf.ts` | Pure TS: `parseGltf(bytes)`, `gltfNodes(doc)`, `decomposeMatrix`, and `spawnGltfScene(ctx, path, opts?)` which turns every node into entities (below). No Three.js, so simulation plugins and Node tests use it. |
| `std/assets` (`sdk/models`) | `src/plugins/std-assets` | `Models.instance(ctx, url)` for `Renderable.model`: official Three.js `GLTFLoader` + `MeshoptDecoder` + `KTX2Loader` (Basis transcoder served from `vendor/basis/`). Geometry, materials and textures are shared between instances and disposed with the last owner. `url#<node index>` instances one node without its child nodes. |

Paths are relative to the site root (files under `public/`, copied by dev and build). Absolute paths, `..` and URL
schemes are rejected. In Node (tests) the same paths read from the repository's `public/` folder.

## Preloading

```json
{ "id": "mygame/level", "sdk": "^3.0.0", "preload": ["models/levels/arena.glb"] }
```

The host awaits a plugin's `preload` list (through `HostOptions.beforeActivate`) right before its `activate()`, so
`assets.peek(path)` returns the bytes synchronously there, and `spawnGltfScene` needs no network round trip. A missing
file fails activation with `preload failed for <plugin>`. `Assets.progress` (`total`, `loaded`, `failed`, `pending`)
is there for loading screens.

## Drawing models

```ts
ctx.world.add(e, Transform3D, transform3d({ position: { x: 2 } }));
ctx.world.add(e, Renderable, { model: 'models/weapons/assault_rifle.glb' });
```

Add `std/assets` to the preset (render sync draws a magenta placeholder until the model is loaded, and warns if no
`sdk/models` provider exists). Skinned models are cloned with `SkeletonUtils`; animation clips are loaded but no mixer
runs yet.

## Blender as a level editor: node custom properties

Blender's glTF exporter writes an Object's custom properties into the node's `extras` (enable *Include → Custom
Properties*). `spawnGltfScene(ctx, path)` creates one root entity (pose `opts.at`, parent `opts.parent`) plus one
entity per node with `Transform3D` (glTF hierarchy → `parent`) and, for mesh nodes, `Renderable { model:
"<path>#<node>" }`. Then it reads these properties:

| Property | Value | Result |
|---|---|---|
| `body` | `dynamic` / `fixed` / `kinematic` | `RigidBody`; the entity becomes a world-space root (physics bodies cannot be parented) |
| `collider` | `box` / `ball` / `capsule` / `cylinder` | `PhysicsCollider` sized from the mesh bounds × node scale (offset = bounds centre); implies a `fixed` body when `body` is absent |
| `sensor`, `friction`, `restitution`, `density` | `1`/`true`, numbers | collider options (`sensor` = trigger) |
| `lockRotations`, `gravityScale` | `1`/`true`, number | body options |
| `renderable` | `false` / `0` | no `Renderable` (invisible triggers, collision-only proxies) |
| `prefab` | registry id | `Renderable { prefab }` instead of the mesh |
| `components` | JSON object (string) | each `"component/id": data` pair is added as a component |
| any `namespace/name` key | JSON (string) or scalar | added as component `namespace/name` |
| any other key | anything | handled by a `GltfExtras` registry entry with that id (`apply(ctx, entity, value, node)`), else listed in `unknownExtras` |

Blender properties cannot hold nested objects, so string values that start with `{` or `[` are parsed as JSON. The
result is `{ root, nodes, byName, unknownExtras }`. Anonymous mesh-carrier nodes that optimisers create (quantisation
moves a mesh off a node that has children) are folded into their parent for drawing and collider sizing.

Example: `games/sandbox` spawns `models/levels/sandbox-props.glb` (ramp, barrel stack, lamp with a `sandbox/glow`
light, invisible `sandbox/goal` trigger). Its source `assets/levels/sandbox-props.glb` is generated by
`assets/levels/build-sandbox-props.mjs` with the same extras a Blender export would carry.

## Build step: `npm run assets`

`scripts/assets.mjs` reads `assets/models.json` (`{ src, out, textures? }` entries) and writes optimised GLBs to
`public/models/` with [glTF-Transform](https://gltf-transform.dev/): `dedup`, `prune` (extras kept), `weld`, then
`meshopt` (EXT_meshopt_compression + KHR_mesh_quantization). `"textures": "webp"` also re-encodes textures to WebP
(≤1024 px, via sharp). Hashes go to `public/models/index.json`; `npm run assets -- --check` (part of `npm run check`)
fails when a source changed without a rebuild or an output was edited by hand. Unchanged sources are skipped;
`--force` rebuilds everything. Sample results: assault rifle 91.0 → 29.3 KiB, knife 24.6 → 9.6 KiB.

KTX2 (Basis) textures are decoded at runtime; encoding them needs KTX-Software's `toktx`, so do that offline with
`npx @gltf-transform/cli etc1s|uastc in.glb out.glb` for now.

## Bundling

Plugins import Three.js addons as `three/examples/jsm/...` (allowed for plugins with the `render` capability, see
`VENDOR_PACKAGES` in `scripts/boundaries.ts`). The build's `three-dedupe` esbuild plugin (`scripts/build-config.mjs`)
resolves their bare `three` import to the vendored runtime, so there is one copy of Three.js. The Basis transcoder
(`basis_transcoder.js` / `.wasm`) is copied from `three/examples/jsm/libs/basis` to `vendor/basis/` by dev and build.
