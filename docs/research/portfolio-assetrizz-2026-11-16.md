## Accessibility and performance

Keep card names, action labels, resource counts, puzzle state and objectives as real text; images supplement rather than encode the only meaning. Decorative images should have empty alt text or be hidden from accessibility APIs; meaningful standalone images need concise descriptions. Preserve keyboard-operable buttons, visible focus, live status, and sufficient contrast on a stable backing/overlay; never communicate state by color alone. Test layouts and crops at narrow widths, zoom, reduced motion and with images unavailable.

Prefer existing small generated painters for in-world use and reuse shared images rather than duplicating data. Measured examples: `assets/experiences/arcade/race-backdrop.png` is 320×180 and approximately 104 KiB on disk; `public/assetrizz/hollow-bg-forest.png` is 1280×720 and approximately 2 MiB, and `cinder-hall.png` is approximately 1.7 MiB. Large plates can dominate load and decode memory; load only when needed, reserve dimensions to prevent layout shift, and consider appropriately sized, provenance-recorded derivatives. The three generated theme modules are approximately 116 KiB, 36 KiB and 276 KiB on disk respectively; synchronous painters avoid image requests but add bundle/decode work, so measure both routes rather than assuming either is free.
